## Implementation

- `main.dart` 按平台选择启动入口：Web 使用 A 示例，原生在系统应用支持目录打开 `reader.sqlite`。加载失败显示重试，拒绝打开更高版本的数据库，不删除或重置已有数据。
- SQLite schema 1 保存订阅、文章及正文版本、归档和外观偏好。抓取合并、阅读状态与偏好写入使用事务；写入失败恢复已提交状态并提示，重试成功后清除错误。
- 保存阅读操作时，只将状态字段合并到数据库当前记录，避免多源刷新中旧内存覆盖已提交的新正文。抓取期间固定正在阅读的版本，更新须通过 RSS 正文入口主动切换。
- 接收 RSS 2、RSS 1 / RDF 与 Atom，处理 `content:encoded`、Atom HTML / XHTML / text、`xml:base` 和原网页链接。Atom 引用外部正文时保存源中已有的摘要。保留段落文字，过滤脚本与样式；不保存图片或承诺源站排版。支持 UTF-8、Dart 内置的声明字符集及带 BOM 的 UTF-16，其他编码提示暂不支持。
- 同源身份以规范化后的 URL 为准：去除两端空白与 fragment，使用 URI 的主机名和默认端口规范化。条目标识优先 GUID / Atom ID，然后原网页链接，缺失时用标题与日期散列；二者也缺失时加入正文。无标识且无链接的条目如果同时改标题或日期，可能成为另一条文章。
- 正文版本根据输入正文和来源链接计算；刷新保留既有版本、阅读位置、状态与快照。保存中的文本更新为空时，仍可续读上次版本。
- 每次订阅请求限时 20 秒、正文大小上限 8 MiB。逐源刷新并展示进度、失败原因；单源失败不阻止其余源更新。
- 应用启动、返回前台、前台每 30 分钟及手动操作会刷新。后台取消定时刷新，已发出的请求可以完成；操作进行中不会重入，退出时释放计时器、HTTP client 和数据库。
- 添加表单、空态、浏览器打开、已读与归档入口接入真实数据；短正文在主动向下阅读后标为已读。同步、AI、自动化、备份及缓存管理面板明确显示尚未开放。
- Android 添加网络权限并允许用户填写 HTTP 订阅；HTTPS 继续使用系统信任。CI 的 SQLite 控制器测试与真实订阅界面测试各有独立步骤。

## Spec

首次审查发现三项行为问题，均已修复并静态复核闭合：

- P1：多源刷新逐源提交后，阅读操作可能将旧正文覆盖回数据库。状态写入改为事务内合并状态字段，并增加“一个源已更新、另一个源仍等待时切换阅读、收藏和保存进度”的回归。
- P2：刷新期间切换文章或再次添加当前订阅可能自动替换正在阅读的版本。固定抓取入口及阅读切换的正文版本，回归确认原位置和最新正文都保留。
- P2：Atom `content src` 使已有摘要被忽略。外部正文条目改用现成摘要，并保留其文本类型与文章链接。

Standards：初审及复核均为 0 项；Spec：初审 3 项，复核剩余 0 项。本增量没有缺失整项范围或无依据扩展。
