## Scope

- Android / Windows 使用系统文件选择器导入和导出 OPML；导入先保存订阅，可离线执行，再由用户刷新获取正文。
- 同源 URL 规范化后合并，重复导入不覆盖已有名称、分类、文章状态和归档；无效条目跳过并报告，格式错误不修改阅读库。
- 导入嵌套文件夹时以分类路径展示；导出保留名称、地址与分类。根级订阅归入“未分类”。
- 可修改订阅名称及分类，新分类随输入创建，无订阅的分类不再显示；订阅地址作为身份保持不变，更换地址通过添加新订阅完成。
- 退订前说明影响。退订停止后续抓取，已保存文章、阅读状态、收藏和归档保留；明确重新添加或导入可恢复订阅。
- Web 继续作为 A 的内存示例。图片缓存、局域网同步、备份和跨设备配置冲突不属于本次增量。

## Implementation

- 系统文件选择器通过 `file_picker` 接入；导入最多 8 MiB，流式读取也检查上限。共享 XML 编码读取支持 UTF-8、带 BOM 的 UTF-16 和 Dart 内置的声明字符集，导出为 UTF-8 OPML 2.0。
- OPML 先完整解析，再以一个 SQLite 事务导入；有效订阅按规范化 URL 合并，保留已有设置和阅读数据，报告新增、合并和无效数量。只导入清单，不要求联网，用户刷新后获取正文。
- 分类显示导入路径，同时保存原始文件夹层级；名称中包含“ / ”时导出不会误拆层级。重复导入及只修改订阅名称保留原分类信息。
- 订阅编辑只更新名称与分类字段；退订保留来源记录和所有已保存文章。既有 SQLite schema 1 数据缺少退订字段时视为正在订阅，不需要重建数据库。
- 请求开始时保存本机退订修订号，提交前重新比较；期间即使经历导入恢复后再次退订，晚到响应也不能撤销后一次退订。主动重新添加或导入可以恢复订阅。保留内容继续从文章列表、收藏、归档和续读入口访问。
- 设置和添加面板均有管理入口，手机可按分类或指定订阅阅读；桌面分类由本地订阅生成。OPML 的数据范围、取消、失败及重试结果在面板内显示。
- CI 为订阅管理控制器和界面各增加独立测试步骤，保留既有示例及真实阅读测试。
