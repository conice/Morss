## 产品定位与交付范围

面向个人的多设备 RSS 阅读器。核心体验是：在一台设备上阅读，离线期间继续操作，设备重新连接同一局域网后同步变化，并在另一台设备上接着读。

日常使用不要求维护常驻服务器或手工复制数据库。订阅源抓取可以访问互联网；设备之间的阅读数据同步只走局域网。

| 交付阶段 | 范围 |
| --- | --- |
| 基础版 | Android、Windows；RSS / Atom、OPML、分类、标题搜索、离线阅读、已读与续读、局域网同步、收藏归档、备份恢复 |
| 扩展版 | 在基础版上增加公开网页全文提取、本地全文搜索、历史归档管理、自动化、翻译、摘要、要点及当前文章问答；支持与相邻旧版混用 |
| 后续扩展 | 按实际设备需求扩展 iOS、macOS、Linux；自动分类、应用外工具联动、专用翻译引擎与本地模型另行讨论 |

扩展版在应用内提取公开网页正文，保存后离线阅读，通过本地全文搜索找回文章和收藏的历史快照，并按用户配置的规则自动处理新文章。

扩展版还支持整篇文章或选中文本翻译、原文与译文逐段对照，以及文章摘要、要点提炼和当前文章问答。翻译默认目标语言为简体中文，可选择其他目标语言。

继续使用 Flutter 与 SQLite。设备之间的数据同步只走局域网，无需维护常驻服务器；订阅抓取与全文页面获取可以访问互联网。翻译和 AI 使用用户自行配置的第三方在线 API：填写服务 URL 与 API Key，自动从该服务拉取模型列表供选择，按任务发送所需正文与输入，费用由用户的服务账户承担。

- Q24：优先改善 RSS 只有摘要时的阅读体验，增加全文提取，以及已保存正文的全文搜索。关键词筛选现纳入扩展版自动化，首批动作见 Q42 和 Q60；自动分类留作后续增强。
- Q25：默认继续支持 Android、Windows；出现明确的新设备需求时，再选择一个平台扩展并验证跨平台同步。
- Q26：支持相邻版本混用。订阅、已读和收藏继续互通；新增功能在旧端降级展示，旧端参与同步不能导致新数据丢失。基础版同步协议设计需要提前考虑这一要求。

## 平台与界面

- 基础版交付 Android APK 和 Windows 桌面包。
- 使用 Flutter 构建客户端，使用 SQLite 保存各设备的本地数据。
- Android 包通过 Linux 构建环境生成，Windows 包通过 Windows 构建环境生成，采用 CI 构建路线。
- 后续扩展目标为 iOS、macOS、Linux 原生客户端。

2026-09-12 当前工作环境为 Android 13 / Termux，CPU 为 arm64。Flutter 3.47.4、Dart 3.13.3 与 Chromium 149 已可运行，界面任务已执行状态测试、组件测试、静态分析和 Web 构建。完整 Android 构建工具链、Windows 构建环境及原生 CI 尚未落实；安装包构建、安装和原生运行验证仍需在对应环境中完成。

## 缓存、收藏与历史归档

- 普通正文缓存默认保留 30 天，各设备分别管理；仍有普通生成结果引用的准确原文按 Q80 延长保留。
- 已读记录长期保留。
- 收藏状态以及所有保留归档的正文、已下载图片通过局域网同步；归档长期保留，取消收藏不改变其保留、同步与备份范围。
- 退订时保留收藏及仍保留的归档。
- 基础版归档内容以 RSS / Atom 订阅源实际提供的内容为准；扩展版按 Q29、Q50 保存所选正文。
- 收藏保存当时的内容快照。源站更新不会自动替换快照，用户主动重新归档时才更新；并发保存的不同版本均保留。

如果接续阅读的设备缺少普通文章正文，可以在同网时向其他设备补取仍存在的正文和图片缓存。若所有设备都已经清除缓存，则显示原文入口。

普通缓存按期限清理；保留的归档承担长期离线保存用途，包括已经取消收藏的文章归档。

## 局域网同步与冲突

同步订阅源、分类、已读状态、收藏标记、阅读位置，以及所有保留归档的正文和已下载图片；取消收藏的文章归档仍在同步范围内。

每台设备保留独立数据库，通过交换增量修改进行同步。优先传输阅读状态，随后传输收藏正文和图片；文件支持断点续传。重复传输和重试不能产生重复记录，已提交的本地修改不能因同步中断而丢失。

保证同步的条件是：设备处于同一局域网，两端应用同时打开。满足条件时自动同步，也提供手动同步按钮、最后成功时间和未完成项。后台同步作为额外便利，不能依赖它保证完成同步。

设备不在同一网络时，可以分别阅读和修改数据，等待下次具备同步条件时合并。

首次通过一次性配对码确认设备，之后识别已配对设备。同步传输加密，用户可以查看已配对设备并撤销授权。

### 配对授权撤销

| 决策 | 已确认行为 |
| --- | --- |
| Q83：撤销配对授权的传播范围 | 撤销信息向其余已配对可信设备同步；发起端立即停止与被撤销设备同步，其他设备收到后也拒绝它。离线设备在收到变更前无法立即生效，重新加入需用户明确配对；撤销授权本身不删除对方已经保存的数据 |

| 冲突 | 结果 |
| --- | --- |
| 已读与未读 | 保留未读 |
| 收藏与取消收藏 | 保留收藏 |
| 不同阅读位置 | 保留更靠后的位置 |
| 已删除订阅与旧设备带回的旧订阅数据 | 保持删除，不自动恢复订阅 |
| 同一收藏的不同归档版本 | 保留这些版本 |

用户主动从备份恢复选中的订阅、收藏状态或保留归档，属于新的修改，可以继续同步；单独恢复归档不自动将文章标为收藏。

### 同步配置冲突

| 决策 | 已确认行为 |
| --- | --- |
| Q81：同步配置的并发冲突 | 有明确先后关系时以后一次为准；同一服务配置的并发修改保留完整双方版本，暂停受影响的生成，用户选定后继续，不拼接不同版本的地址和模型。订阅名称、分类归属等其他配置的冲突也保留双方值供选择；按源自动提取开关并发冲突时关闭优先 |

| Q45：触发时机与历史文章 | 刷新订阅发现新文章时自动触发；创建或修改规则默认只影响后续新文章。已有文章先预览，再由用户手动批量执行；同步接收结果不重新触发规则 |

| Q49：多设备执行 | 规则通过局域网同步，各设备可在离线时处理自己新抓取的文章；执行仍遵守本机的网络与运行条件。重试或重复同步不重复修改状态，也不重复创建相同的自动归档快照；不同设备实际归档的内容不同，保留不同版本 |
| Q50：自动收藏与提取失败 | “提取全文后收藏”对尚未收藏的文章生效：成功时收藏全文，提取失败时收藏已有 RSS 内容并记录失败。已有收藏继续遵守手动重新归档规则，后续提取成功不自动加入新快照 |

Q48 的操作来源优先级适用于本机执行与跨设备合并。Q49 的防重复要求针对可见状态和归档结果，离线设备独立访问原网页时可能各自发生网络请求。

### 规则管理、记录与恢复

| 决策 | 已确认行为 |
| --- | --- |
| Q51：规则修改、停用与删除 | 本机立即生效，其他设备收到同步后生效；离线设备在收到变更前可能按旧规则执行。修改、停用或删除后，停止受影响规则尚未提交的动作，保留已完成结果；重新启用或新规则默认面向后续文章 |
| Q52：规则与排序冲突 | 并发编辑同一规则或修改执行顺序时保留各个版本，暂停自动规则执行，选定版本或顺序后继续。停用或删除与编辑并发时，停用或删除优先；有明确先后关系时以后一次用户修改为准 |
| Q53：与按源自动提取配合 | 已有按源自动提取设置继续独立生效。自动化规则和按源设置请求提取同一篇文章时，本机复用缓存或合并同一提取任务，分别处理各自后续动作；规则顺序只控制规则之间的匹配 |
| Q54：执行记录与纠错 | 默认保留最近 30 天的可读执行记录，展示规则、命中或跳过原因、文章、执行设备及结果。支持按执行批次撤销自动标已读和收藏状态，但只回退仍由该批次决定、之后未被修改的字段；正文和归档文件继续保留。清理可读日志不清除防重复所需记录 |
| Q55：旧版设备 | 旧版展示和同步自动化产生的已读、收藏及归档结果，保留不认识的规则与执行元数据，由新版管理和执行规则。旧版真实的手动操作或阅读行为仍优先于规则结果；转发结果不改变其来源 |
| Q56：规则备份与恢复 | 备份包含规则、顺序、启用设置及防重复所需记录。恢复后，本机自动化先暂停，用户预览后再启用；这项暂停只作用于恢复设备，不同步成全局停用。已有数据时可选择恢复规则，作为新修改合并 |

### 执行规则的衔接

以下明确自动化与已确认的阅读、缓存及任务规则如何共同生效。

| 情况 | 行为 |
| --- | --- |
| 手动改变某项状态 | 用户行为优先级按字段判断。手动标为未读会阻止规则再次标已读，但不自动阻止与该字段无关的全文提取；初始未读、未收藏等默认值不构成手动决定 |
| 历史文章批量执行 | 先预览再执行；批次中的动作仍属于规则动作，继续遵守用户行为优先级和已有收藏的归档限制 |
| 一条规则已经命中 | 该轮不继续执行后面的规则；动作被用户行为保护而跳过、或动作失败，不改为执行另一条规则。无法判断正文条件的规则按 Q46 跳过 |
| 等待网络、暂停或空间不足 | 沿用已有任务状态，等待满足运行条件；这些状态不作为提取失败触发自动收藏回退 |
| 提取仍失败 | 沿用有限重试规则，最终失败时按 Q50 收藏已有 RSS 内容并记录失败；已经收藏的文章不自动重新归档 |
| 翻译或摘要需要全文 | 依 Q72 先取得规则所选正文，未取得所需全文则跳过对应生成并记录原因；收藏的 RSS 回退仍按 Q50 处理，不把 RSS 摘要冒充全文生成结果 |
| 生成与收藏串联 | 网络、额度或用户暂停使后续动作等待；生成失败或结果不明时可继续不依赖该结果的后续动作。首次收藏附带本次对所选原文完整生成或复用的结果，缺少结果仍可收藏原文；已有收藏不自动追加，之后补齐结果需用户主动保存 |
| 规则取消、修改、停用或删除 | 按 Q51 停止尚未提交的动作；取消不触发失败后的收藏回退。提交状态或首次归档前需检查规则仍有效、且没有应优先保留的用户行为 |
| 多个入口共用提取任务 | 每个入口的后续动作分别判断是否仍有效；停止某条规则不取消其他入口仍需要的提取。已经提交的结果继续保留 |
| 编辑冲突导致暂停 | 保留未处理事件，选定规则版本或顺序后继续处理待执行事件，已经完成的文章不自动重跑。主动修改或重新启用规则的作用范围仍按 Q45、Q51 处理 |
| 批次撤销 | 仅回退仍由该批次决定、之后未被修改的已读或收藏状态，撤销结果参与同步；后来收到的用户修改也必须受到保护。正文和归档文件继续按既有保存规则保留 |
| 日志到期 | 最近 30 天的可读执行记录与防重复所需元数据分别管理；日志到期或被清理，不成为重新执行旧动作的理由 |

## 翻译与 AI

翻译和 AI 作为扩展版新增模块，Q57–Q77 已确认；Q73–Q77 规定第三方 API、自填 URL / API Key、自动拉取模型及异常处理。Q77 对 Q62 的计数口径作了细化，以下条款已同步更新。

| 决策 | 已确认行为 |
| --- | --- |
| Q57：翻译阅读体验 | 自动识别原文语言，默认翻译为简体中文，并允许选择目标语言；支持整篇文章和选中文本翻译，提供原文与译文的逐段对照，保留原文 |
| Q58：AI 的首批用途 | 优先提供文章摘要、要点提炼和针对当前文章的问答；摘要及回答中的文章依据可以定位到对应原文段落 |
| Q59：服务方式与费用 | 接入用户自行配置、使用自带 API Key 的第三方在线服务，费用由用户的服务账户承担；翻译、摘要及问答仅向所选服务发送当前任务所需正文及用户输入，模型测试按 Q77 发送简短固定测试文本。设备间数据同步继续只走局域网 |
| Q60：触发与自动化 | 默认由用户手动发起翻译、摘要或问答；允许在指定自动化规则中增加“翻译”和“生成摘要”动作，并逐条启用。文章问答保持手动发起，自动调用沿用本机网络与运行限制 |
| Q61：输入范围与长文 | 处理当前选中的正文版本或选中文本；仅有 RSS 摘要时明确标注处理范围，需要全文时先提取。长文按段落分批处理，显示进度与覆盖范围，保留代码、链接及段落对应关系 |
| Q62：调用额度与费用 | 默认每台设备每日最多 50 次文本生成调用、每次输入最多 1 万字符，均可调整；手动、自动、分段请求、重试及 Q77 的模型测试共用额度，读取模型列表不占生成额度。达到额度后暂停新的生成及测试请求，仍可读取模型列表；有服务用量和单价时显示估算费用，实际账单以服务方为准 |
| Q63：结果保存与同步 | 译文、摘要和问答记录关联到对应原文版本，记录服务、模型、语言及生成时间。普通结果默认缓存 30 天，可通过局域网补取；用户可以将选定结果连同原文保存到收藏，长期保留并同步。生成结果作为附加内容保存，原文继续保留 |
| Q80：普通结果与原文共同保留 | 保留普通生成结果期间，一并保留它所依据的准确原文版本及段落关系；最后一个相关普通结果过期后，原文恢复按自身缓存规则清理。用户主动清理时说明关联范围，并一并清理将失去依据的本机普通结果；长期归档及其他设备的副本继续遵守各自规则 |
| Q64：文章问答依据 | 基于当前选定的文章正文回答，提供可定位到原文段落的依据；正文没有足够信息时明确说明。问答范围限定为当前文章，引用必须对应实际存在的原文段落 |
| Q65：服务配置与密钥 | 翻译、摘要和问答默认共用一组服务配置，也允许分别指定。API 密钥保存在本机系统安全存储中，跨设备同步和应用备份仅包含不带密钥的配置；密钥不进入日志，其他设备各自配置密钥 |

服务提供方及模型由用户配置，应用不固定为某一家服务商。首批按 Q74 接入 OpenAI 兼容接口，价格及实际接口能力需以所配服务核验。Q62 为应用侧的可配置默认限制，并非对服务价格或模型容量的承诺，也不是整个服务账户的消费上限；不同设备的额度分别计算，费用估算与服务方账单分别呈现。长文分段、后续汇总及模型测试产生的各次文本生成调用均受这些限制约束。

新增自动化动作继续遵守新文章触发、历史文章先预览、规则顺序、规则变更生效范围与本机恢复后暂停等已确认规则。Q37 的有限重试适用于全文提取和下载；翻译与 AI 的请求恢复、重试和重复调用按已确认的 Q66、Q67 处理。

### 请求、结果和服务接入

| 决策 | 已确认行为 |
| --- | --- |
| Q66：付费请求失败与重试 | 已发出的文本生成或模型测试调用失败、超时或退出后结果不明时，不自动重新发送，显示失败或“结果不明”并等待用户手动重试。保留已完成段落，部分结果标明未完成及覆盖范围；手动继续只补未完成部分，无法取得结果的请求再次发送仍可能收费。仅因等待运行条件而尚未发出的部分，在条件恢复后继续；已经失败或结果不明的任务余下部分等待手动继续，用户主动暂停或取消后不自行恢复。取消停止后续发送，不能保证撤回服务已接受的请求或免除其费用。所有实际发出的文本生成及测试调用按 Q62 计数，超时不退还本机已计次数；模型列表的获取与失败回退按 Q75、Q77 处理 |
| Q67：复用与重复调用 | 发起请求前优先查找本机及当前可连接的已配对设备上的完整结果；同一原文版本、处理范围、任务类型、目标语言、服务与模型以及生成参数和输入相同才可复用，本机相同的在途请求合并。问答由用户发起，复用还需问题及所用对话上下文相同。没有可复用结果时按正常条件调用；设备彼此未连接或同时调用时仍可能重复收费，不承诺跨设备外部请求只发生一次 |
| Q68：重新生成、原文更新与删除 | 手动重新生成会发起新的调用并保存新结果，已有结果按各自缓存或归档期限保留。原文更新形成新版本，旧结果继续关联旧原文，不自动改绑或重新生成。清理普通结果只影响本机；删除选定归档结果通过局域网同步，保留原文及其他结果，旧设备重连不将其恢复。删除某份原文归档时，先列出并一并删除该归档所附结果，其他归档不受影响 |
| Q69：译文续读与已读状态 | 原文与译文通过原文段落对应，共用该原文版本的阅读位置，切换语言或对照方式时尽量对齐；无法对齐时提示并按已有回退规则处理。完整译文读到末尾按正文阅读规则标为已读；生成结果、只看选中文本的翻译、摘要、要点或问答均不自动表示读完整篇文章 |
| Q70：生成内容搜索 | 已保存在本机的译文默认参与全文搜索，摘要与问答可通过筛选项选择纳入。结果标明原文、译文、摘要或问答及其语言、所属原文版本；同文合并展示，点击片段进入实际命中的内容。多个关键词需在同一份可检索内容及其标题范围内全部命中，不能跨原文、译文或不同生成结果拼接；内容清理后移除相应正文命中 |
| Q71：旧版兼容与备份恢复 | 旧版继续阅读原文并保存、转发不认识的生成结果及元数据，由新版提供翻译和 AI 的展示与操作。归档结果、原文关联和段落对应关系随收藏备份，普通生成缓存不备份；恢复后重建相应搜索。新版没有 API Key 时也能离线阅读已保存结果，恢复备份或补填密钥不自动重新生成；恢复设备仍遵守本机自动化先暂停的规则。服务配置按 Q65 备份且不含密钥 |
| Q72：自动生成与收藏串联 | 规则中的翻译或摘要动作明确选择 RSS 正文或提取全文；需要全文时先安排提取，未取得所需全文则跳过对应生成并记录原因。等待网络、额度或用户主动暂停时保留执行位置，暂停后续动作；生成失败或结果不明时记录状态，继续不依赖生成结果的后续动作。首次收藏保存所选原文及本次对该原文完整生成或复用的结果，缺少生成结果时仍可收藏原文；提取失败后的 RSS 收藏回退继续按 Q50 处理。已有收藏不自动追加版本，之后重试得到结果也需用户主动保存 |
| Q73：第三方服务配置与模型获取 | 翻译、摘要和问答使用用户自行配置的第三方在线 API。用户填写服务 URL（Base URL）与 API Key，应用自动从该服务拉取模型列表供选择，可按 Q65 共用配置或分别指定。首批提供经验证的服务模板，同时保留自定义地址入口，不固定服务商或内置模型名单；具体模板须在所对应服务验证后确定。专用翻译引擎与本地模型留作后续扩展 |

## 第三方 API

Q74–Q77 的接入细则已确认。设置流程为填写服务 URL 和 API Key、自动获取模型列表、由用户选择模型；模型列表不可用时允许手动填写模型 ID。读取目录与执行文本生成分别展示结果，模型目录不作为任务能力或价格的保证。

| 决策 | 已确认行为 |
| --- | --- |
| Q74：首批接口兼容范围 | 首批支持 OpenAI 兼容的模型列表与 Chat Completions 文本接口，允许自行填写第三方 Base URL 和 API Key，不限定服务商。Base URL 定义为完整接口前缀，保留服务商的路径，只追加 `models` 或 `chat/completions`，不固定加上或重复拼接 `/v1`；完整生成端点不能直接当作此前缀。不兼容此接口的服务需另行适配，不能仅凭填入 URL 就视为支持 |
| Q75：拉取时机与失败回退 | 首次保存格式正确的配置、或更新 URL / API Key 后自动拉取模型列表，并提供手动刷新。保留最近成功列表及获取时间；拉取失败或列表为空时展示原因，允许使用同一服务配置的缓存列表或手动填写模型 ID。获取模型目录失败不直接判定生成接口不可用，仍可保存配置；旧目录明确标为缓存 |
| Q76：模型选择、失效与配置变更 | 自动获取列表后由用户选择模型，不自动把列表第一项用于生成；翻译、摘要和问答继续按 Q65 共用或分别指定。模型从目录消失时标为未列出并保留选择；实际调用报告模型不可用时暂停受影响的生成，等待用户更换，不静默切换其他模型或服务。更改服务地址后不沿用旧服务的列表、可用性结论或模型选择，需重新选择或填写；已保存结果继续可读 |
| Q77：可用性测试与调用额度 | 自动发现只读取模型目录，不自动发送文本生成探测。提供用户手动触发的“测试当前模型”，使用简短固定测试文本，不发送文章；成功只说明本次文本请求可用，不保证所有任务、模型容量或后续调用均成功。模型目录读取不占 Q62 的生成调用额度，所有实际发出的文本生成及测试调用仍计数，测试前说明可能由第三方计费 |

下文验收覆盖服务配置、模型目录、模型失效和测试调用。具体第三方服务及模板在适配完成后验证，通过对应检查才能列为已验证支持；首批接口范围已经确定，具体服务的兼容性仍以验证结果为准。

接口事实核对（2026-09-12）：OpenAI 官方文档的[模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)为 `GET /v1/models`，[Chat Completions 文本生成](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)为 `POST /v1/chat/completions`，使用 Bearer API Key 鉴权。模型目录提供 ID 等基础信息，不构成文本生成能力、参数、容量或价格的保证。这些资料用于 Q74 的接口设计参考；第三方服务是否实现相同接口，仍须分别验证。保留完整 Base URL 前缀的拼接方式是 Q74 已确认的设计约定。

## 备份、恢复与版本兼容

### 备份与恢复基础

- 每天首次启动时自动生成本地备份，保留最近 7 份。
- 备份包含订阅、阅读状态和所有保留归档等恢复所需业务数据，包括已取消收藏的文章归档；配对凭据和 API Key 不进入应用备份。
- 支持手动导出备份文件；导出备份使用密码加密。
- 空设备可以完整恢复。
- 已有数据时，允许选择需要恢复的订阅、收藏状态或保留归档，将其作为新修改同步，并保留其他设备更新的阅读进度；单独恢复归档不自动将文章标为收藏。
- 换机前可以把导出的备份复制到其他设备保存。

### 相邻版本兼容

已确认支持相邻版本混用，基础版同步协议和数据保存方式需要提前满足以下约束：

- 订阅、已读和收藏继续互通，旧版参与同步不能清除它不认识的新增数据。
- 旧版可以将全文快照作为普通收藏正文阅读；全文提取、正文搜索和历史版本管理由扩展版提供。
- 新版保存的其他正文版本和阅读位置不被旧端回传覆盖；已经删除的历史快照不会因旧设备重连而自动恢复。
- 扩展版增加自动化后，手动操作与实际阅读产生的状态优先于规则自动修改，按已读、收藏等字段分别判断。基础版需保留操作来源，区分初始默认值与真实用户行为，回传已有结果不能将其伪造成新的用户操作。
- 自动化规则由扩展版管理和执行；基础版保留其规则、执行顺序、启用或删除状态与必要的执行元数据，正常展示产生的阅读状态和归档结果。
- 扩展版生成的译文、摘要和问答由新版展示；旧版继续阅读原文，保存和转发不认识的生成结果、原文及段落关联和删除信息。已删除的归档结果不因旧设备重连而恢复，密钥不进入同步数据或应用备份。
- 收藏标记与归档按 Q79 独立保存；旧版参与同步不能因取消收藏而丢弃保留归档。
- 设备身份与授权按 Q82、Q83 管理；旧设备回传历史数据不能恢复已撤销授权，配对资料不从备份重新启用。
- 遇到无法识别的新备份格式时，旧版拒绝恢复并提示升级，保留现有数据。

| 升级失败 | 修改数据前先备份；备份或升级失败时明确报错并保留可恢复的原有数据，不将未完成的升级当作成功 |
| 恢复与删除 | 空设备恢复备份所含完整业务数据；已有数据时，选择恢复的订阅、收藏状态或保留归档作为新修改，保留其他设备更新的阅读进度。用户主动恢复已删收藏或归档与旧设备自动带回旧版本区别处理；单独恢复归档不自动将文章标为收藏 |

基础版同步协议和数据保存方式必须提前满足相邻版本兼容要求：旧版参与同步不清除新增数据，能够将全文快照作为普通收藏正文阅读，并且不自动恢复已删除的历史快照。旧版保存和转发自动化规则与执行元数据，展示产生的状态和归档结果，由新版管理和执行规则。旧版继续阅读原文，保存和转发生成结果及其原文关联、段落关系和删除信息，由新版展示翻译与 AI 内容。旧版也需要在不支持新备份格式时拒绝恢复，保留现有数据。

扩展版继续遵循本文件的订阅、阅读、界面、同步、授权与备份基础条款，包括同步优先传输阅读状态、局域网文件断点续传、退订保留收藏和长期保留已读记录。

提取验收应准备可重复使用的中英文页面样例，覆盖段落、图片、链接、列表、表格、代码及失败回退。自动化样例覆盖命中、未命中、缺正文、已有手动决定、重复事件与离线冲突；另加入重复 OPML、同源更新、跨源转载、取消收藏后归档保留、最后快照删除、多端配置冲突及配对撤销传播。

翻译和 AI 样例还需覆盖仅有 RSS 摘要、多个原文版本、选中文本、长文分段、代码与链接、正文中缺少答案，以及手动与自动请求共享额度、付费超时与取消、相同及不同输入复用、旧设备重连后的删除保留、译文续读和生成搜索。第三方 API 样例覆盖自定义路径前缀、目录为空或失败、手填模型、模型下架、切换服务、替换密钥、每日额度用尽，以及目录读取和手动测试产生的不同请求。模型目录可读取但生成失败、目录不可读取但手填模型可生成这两类服务行为均需覆盖；普通结果的样例还需跨越原文缓存到期，并验证关联清理、原文补取和未归档内容不进入备份。

规模测试记录设备配置、实际保存的正文与版本数量、图片体积、启用规则数量与条件复杂度、提取和查询耗时、规则处理耗时、同步耗时及存储占用。

规格未约定启动、查询或同步速度的数值承诺。测试应报告实测结果；安装包构建及平台运行验证仍需在“平台与界面”所述的对应环境完成。
